# 项目与生产一致性维护

本页记录代码、配置与运维入口的检查方法及维护结论，不记录用户明细、邮箱清单、账号数量或生产凭证。

## 一致性检查

核对以下层次，而不是只比较 Git 分支名：

1. **Worker 代码**：从 Cloudflare 获取实际部署模块，与本地 Wrangler 构建产物比较。比较时排除纯 sourceMappingURL 差异，不把源码存在等同于代码已发布。
2. **Worker 配置**：兼容日期、账号 origin、D1 绑定、自定义域名和 Cron 应与 wrangler.jsonc 一致；生产 Secret 只检查绑定是否存在，不输出其值。
3. **D1 schema**：对照迁移脚本检查表、索引和触发器，不为“保持一致”重灌用户数据。
4. **本机网关**：核对真实进程、工作目录、Worker 连接模式和上游地址，避免文件已改但进程仍运行旧代码。
5. **静态页面与公网行为**：核对账号首页、静态资源、D1 健康、网关健康、未授权拒绝和内部接口保护。

维护前检查确认：Worker 模块与本地构建一致，生产 D1 的业务 schema 与迁移定义一致，域名与本机网关配置匹配。因此没有通过重建库或重新导入数据来处理代码维护。

页面核对时，HTML 可能包含 Cloudflare 边缘自动注入的统计脚本及附加换行。应明确识别该受管理的附加内容，再比较业务 HTML，不能把任意脚本差异都忽略。本次应用 JS/CSS 与本地逐字节一致，排除已确认的 Cloudflare Insights 注入后，HTML 业务内容一致。

## 修补的实际问题

| 问题 | 修补 |
|---|---|
| API Key 语音客户端仍要求服务器 Client ID 文件 | API Key 只带自身凭证；登录令牌才读取 Client ID |
| 文件客户端默认连接内部模型端口，依赖已拆走的环境 | 默认连接公网网关，模型环境不作为客户端依赖，语音库改为可选依赖 |
| 未配置 Worker 时，启动入口可静默使用历史 SQLite | 服务器默认要求 Worker 配置；本地模式必须显式启用 |
| 账号 CLI 容易被误用于线上用户管理 | 本地 CLI 要求 --local-only，导出与离线迁移要求显式源库/目标库 |
| Worker 对 services=null、空服务的新用户、days=null 处理不严格 | 返回明确的 422，不把无效权限写入数据库 |
| 内部账号 RPC 的成功响应缺字段时会产生异常或不明确的额度值 | 检查 lease、剩余额度和确认字段；畸形响应按账号服务不可用处理 |

这些修补不改变已存在用户、密码或密钥，不需要数据迁移。回归测试使用隔离的 SQLite、HTTP mock 和 Miniflare/D1。

## 移除的失效内容

- 直接往旧 SQLite 建测试账号、依赖本机凭证文件的历史线上 smoke 脚本。
- 针对旧域名的 DNS 退役脚本。
- 已退役账号隧道的元数据、旧隧道重建操作文档。
- 带历史生产数量且不代表当前状态的拆分验证快照。
- 未被当前安装流程使用的旧账号依赖快照。

旧文件仍可通过 Git 历史查阅，不作为当前运维步骤。当前部署检查为 `python -m scripts.smoke.check_deployment`，不创建用户、Key 或模型请求；认证失败探测可能按正常策略更新安全计数。

## 保留的兼容能力

- 旧 Key 协议、额度基线与对应测试仍有业务作用，不能因名称含 legacy 删除。
- 本地 SQLite 实现、明确输入输出的迁移工具继续用于离线恢复和隔离测试，不作为生产用户管理入口。
- 私有备份不属于无用源文件，本次没有删除生产回滚材料。
- API 隧道仍连接本机网关；账号域名直接由 Worker 提供服务。模型未就绪与网关代码漂移分开处理。

## 维护与发布流程

```bash
.venv-accounts/bin/python -m tests.run
cd cloudflare
npm test
npm run check
```

测试通过后提交代码，再发布 Worker，可使用 `--tag` / `--message` 记录 Git 提交，便于后续对照。网关 Python 代码或环境变化时，需要检查在途请求，再重启本机网关；单独发布 Worker 不会更新本机进程。

发布后运行无账号创建的部署检查，并再次比较 Worker 构建和生产配置。日常维护不运行数据导入或账号清理。当前本机服务未配置开机自启，这属于后续部署管理事项，而不是代码与生产的差异。
