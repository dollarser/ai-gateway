# 免费额度优先的资源策略

优先减少低价值自动请求及D1扫描，不新增KV、Durable Objects、队列或推送基础设施。D1计量看实际rows_read/rows_written而非HTTP数量或返回字节，具体以控制台为准：[D1计量](https://developers.cloudflare.com/d1/platform/pricing/)。

本次服务端/网页已实施：

- 普通通告摘要按账号持久化，每24小时最多自动检查一次；同浏览器重复登录/刷新复用状态，失败同样延迟一天。前台恢复/网络恢复只在到期时检查，网页多标签可使用Web Locks协调。不同设备各自检查；存储被禁用时无法保证跨重启去重。
- 通告列表按需加载，已读返回摘要直接更新UI；通告管理区和运维管理区展开后才加载。账号列表翻页/筛选不再顺带重查运维信息和默认额度；默认额度本会话复用，手动刷新重新获取。
- HTML不缓存；JS/CSS采用内容哈希和长期缓存，资产路由直接提供，不进入用户Worker；账号接口不公共缓存。
- 管理员告警取消一分钟轮询，仅打开中心或主动刷新时获取。监测Cron仍为15分钟，保持真实请求的异常检测。
- 正常上游成功不再自动探测出口，省去D1采样槽、诊断结果和外部请求；上游403诊断及管理员主动探测保留。
- 无Cookie/令牌的账号请求直接401，不先查D1。有效凭证、禁用状态和额度仍实时查验。
- 监测窗口的请求数、失败数、地区拒绝和延迟样本数合并一次聚合；样本达到告警门槛（总体20、音频10）才查询P95。少量样本不再排序查询P95。
- 会话按过期时间、登录家族加索引，避免定时清理和撤销时扫描全部活动会话；索引会增加登录/清理时少量写入，避免无依据地给高频推理账本增加索引。

不为了节省额度降低认证、封禁、并发与预算扣减的一致性；不删除财务账本或关闭失败诊断。后台日志仍不记录原始内容/凭据。状态缓存、接口合并、304等不应被计作“零数据库读取”，要实际检查rows_read。

观察效果时优先使用Cloudflare已有D1指标及insights，按需人工查看，不为统计自身增加每请求一条D1记录。全站账本聚合已实施，后续针对个人历史扫描按实际查询计划继续评估，避免无依据增加高频索引。

外部客户端的统一调度、模型缓存、用量刷新、令牌刷新合并及音频取消规则见[客户端交接](client-handoff.md#免费额度优先的客户端协作规则)。

## 进一步利用免费静态托管及固定成本预算检查

生产静态文件由 scripts/ops/build_assets.py 构建到 `.runtime/portal-assets`，只包含公开HTML、JS、CSS和响应头规则，不包含相邻运行凭据。JS/CSS采用内容哈希文件名和一年缓存；HTML不缓存。Wrangler资产路由直接提供静态资源，只有 /auth、/account、/admin、/internal、/healthz、/v1、/ws 和内部诊断前缀优先进入Worker；未知资产仍按平台规则回到Worker。账号和API路径仍由原鉴权处理，不是将API公共缓存。旧静态文件别名继续提供且不缓存，兼容已打开的旧页面。

全站Luna和语音预算使用 luna_spend_totals / audio_spend_totals；迁移0016从历史账本一次性回填，之后由数据库触发器在同一事务内跟随详细账本插入、结算、调整、跨周期移动及删除。用户删除不会删除独立全站账本，因此不会返还已发生全站消费。未知结算继续占预留；未使用缓存或异步同步来决定是否放行。个人额度仍保留原数据库原子校验。

每次发布迁移后执行只读核对，确认汇总与详细账本一致：

```bash
.venv-accounts/bin/python -m scripts.ops.check_spend_totals --remote
```

该命令会扫描详细账本，只用于发布和必要人工核对，不增加定时任务；发现差异则失败，不静默修正金额。备份恢复验证也检查汇总一致性。

本地Miniflare、模拟上游、非流式Luna调用的对照计量（不是生产容量承诺）：

| 场景 | 修改前读取/写入行数 | 修改后读取/写入行数 |
|---|---|---|
| 云模型列表 | 26 / 14 | 2 / 0 |
| 全站月账本5万条，一次Luna | 50061 / 34 | 56 / 36 |

汇总增加少量写入，换取全站账本规模不再线性放大每次请求的读取。个人当月额度及历史管理查询仍可能随个人记录增长，应继续观察实际rows_read。

生产LOCAL_MODELS_ENABLED=false时，模型目录改为只读校验账号/令牌/Key及服务权限；不创建推理请求记录，不扣日请求数和并发名额，也不触发上游调用。封禁、Key撤销和权限调整仍在下次查询立即生效。将来显式开启本地模型目录时仍复用原有带内部凭证的查询路径，可能产生记录。

无需为了Cloudflare网络字节量压缩PCM或关闭SSE：正常保持流式和必要交互，重点避免重复计费请求、逐块查库及无效重连。OpenAI费用、免费Worker CPU上限和邮件服务自身规则仍独立存在。
